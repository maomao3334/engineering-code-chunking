# 从 PDF 到语料库：一次完整的实操记录

> 对象：《纺织工程设计防火规范》GB 50565-2010（40 页 / 172 条 / 3 张表）
> 结论先行：**先体检再动手**。这份 PDF 有三处不体检就会毁掉语料库的地方。

## 第 0 步：体检（决定后面走哪条路）

```python
import fitz
doc = fitz.open(pdf)
total = sum(len(doc[i].get_text().strip()) for i in range(doc.page_count))
print(doc.page_count, total / doc.page_count)      # 40 页, 823 字/页
```

| 体检结果 | 走哪条路 |
|---|---|
| 平均 >300 字/页 | **有文字层 → 直接抽取，跳过 OCR** |
| 50~300 字/页 | 稀疏，逐页判断（可能是双层 PDF） |
| <50 字/页 | 扫描件 → 必须 OCR（双遍 300/600dpi 逐行择优） |

这份 PDF 823 字/页 → **不用 OCR**，直接省掉整条最贵的流水线（原流程 OCR 要跑几十分钟）。

> 但注意：**文字层有 ≠ 全都有**。表格、公式、竖排文字常常仍是图片，见下。

## 三个必须体检出来的坑

### 坑 1：水印混在正文里

每页都有：

```
《纺织工程设计防火规范》GB 50565-2010      中国消防规范网 gf.1190119.com
6
公众号CN00119
```

**不清理的后果**：每一片切片都带"公众号CN00119"，检索时这些词会互相匹配，污染排序。

清理规则（按行匹配，命中即丢）：

```python
WATERMARK = [r"中国消防规范网", r"gf\.1190119\.com", r"公众号\s*CN\d+"]
PAGE_NO   = r"^\s*\d{1,3}\s*(公众号\s*CN\d+)?\s*$"   # 页码与公众号粘连成一行
```

实测清理掉：水印行 34、页码行 39、空行 199。

### 坑 2：「条文说明」是空标记，不是内容

全文出现 **132 次**「条文说明」，但都是紧跟条文末尾的空标签（PDF 里的链接文字），
**后面没有任何说明内容**。

```python
TRAIL_MARK = re.compile(r"\s*条文说明\s*$")   # 去掉行尾标记
```

**必须先判断它是不是空标记**：如果 PDF 是"条文+说明合订版"，条文说明是真内容，
那就该按 `条文类型=条文说明` 单独存，**不能混进条文正文**（会把"制定本规范的目的"讲成答案）。
判断方法：看「条文说明」后面有没有实际段落。

### 坑 3：表格是图片，文字层只有表标题

这是最危险的一个。文字层里能看到：

```
4.1.7 纺织工程中的设施与厂外建筑物或其他设施的防火间距，不应小于表4.1.7 的规定。
表4.1.7 纺织工程中的设施与厂外建筑物或其他设施的防火间距
注：1 标明"注1"栏中的防火间距应符合…（后续 11 条注）
```

**看起来表格完整**，但表体一个字都没有——它在图片里：

```python
for idx in range(doc.page_count):
    for im in doc[idx].get_images():
        if im[2] > 300 and im[3] > 200:      # 宽>300 才是表体，小图是 logo
            ...  # 提取后 OCR
```

不处理表体，就违反**铁律 2**（表格必须进索引）：问"可燃材料堆场与建筑物的防火间距是多少"，
永远答不出来。实测 3 张表全部是图片（545×593、546×488、645×543）。

> **体检方法**：随便挑一条写"应符合表X的规定"的条文，看它的表体文字在不在 `get_text()` 里。
> 不在 = 表格是图片。

## 解析规则（每条都对应一次踩坑）

```python
RE_CHAPTER = r"^(\d{1,2})\s+(\S.{0,30})$"          # 1 总则
RE_SECTION = r"^(\d{1,2}\.\d{1,2})\s+(\S.{0,30})$" # 4.1 总体规划
RE_ARTICLE = r"^(\d{1,2}\.\d{1,2}\.\d{1,3})\s+(\S.*)$"  # 4.1.1 正文
RE_KUAN    = r"^\s*(?:(\d{1,2})\s+|（(\d{1,2})）)\s*(\S.*)$"  # 1 正文 / （1）正文
RE_KUAN2   = r"^\s*(\d{1,2})[）)]\s*(\S.*)$"       # 1）正文 —— 二级款
RE_APPENDIX= r"^附\s*录\s*([A-Z])\s*(\S.{0,40})$"  # 附录A 标题
```

### 踩坑 1：表格注被误判成"章"

表注的形态是 `  1 建筑物的耐火等级应为一级。`——行首数字 + 短内容，完美匹配章的正则。
一份 10 章的规范被解析出 **64 章**。

**修法**：章号必须**递增**（从 1 开始，遇到就 +1），且标题**不能以句读结尾**。

```python
if m and int(m.group(1)) == next_ch and not title.endswith(("；","。","，","：","）")):
```

### 踩坑 2：跨行引用被误判成"新条"

表注里有：`…应符合本规范表4.2.10 的规定；` 折行后变成：

```
4.2.10 的规定；
```

以 `4.2.10` 开头 → 被当成第 4.2.10 条 → 条号重复，且真条被挤掉。

**修法**：加"引用行"识别——条号 + ≤12 字 + 句读收尾，就是引用不是条文。

```python
RE_CITE_LINE = r"^\d{1,2}\.\d{1,2}\.\d{1,3}\s+\S{0,12}[；。]\s*$"
```

### 踩坑 3：单调递增校验会误杀真条

加了"条号递增"后，条数从 173 掉到 163——因为**每节第一条**（X.Y.1）天然回退。

**修法**：`cand[2] == 1`（每节第一条）永远接受，其余必须递增。

### 踩坑 4：标准名称里的"第14 部分"被当成款号

```
…《爆炸性气体环境用电气设备
第14 部分：危险场所分类》GB 3836.14…
```

折行后 `14 部分：危险场所分类》…` 被当成第 14 款。

**修法**：款号必须**紧跟上一款递增**（1,2,3…），且内容不能以"部分"开头。

```python
if no == str(len(cur["kuan"]) + 1) and not rest.startswith("部分"):
```

### 踩坑 5：二级款 `1）2）3）` 被当正文

原文风格：`4 当设置高位消防水箱确有困难时，可设置…：1）系统由…。2）由稳压装置…`

`1）` 是全角右括号单独用（没有左括号）。不处理的话，三小项全塞进第 4 款正文。

**修法**：单独识别 `RE_KUAN2`，挂到上一款的 `sub` 列表；导出时统一成 `（1）`，
否则"括号不配对"检查会误报成 OCR 缺陷。

### 踩坑 6：附录标题被吞进上一条正文

`附录A 纺织工业生产的火灾危险性分类举例` 不匹配章/节/条，被当续行接到 `10.3.5` 末尾，
导致 `10.3.5` 正文里出现"附录A…附录B…"整段。

**修法**：单独识别 `RE_APPENDIX`，终止当前条，并把附录作为独立"章"记录。

### 踩坑 7：表注的**续行**被当正文吞掉（交付后复核才抓到）

这一条是**交付后独立复核才发现**的，自动校验完全查不出——因为它不影响任何结构指标。

现象：`4.2.10` 原文只有一句

```
4.2.10 工厂总平面布置的防火间距不应小于表4.2.10 的规定。
```

但语料库里，正文后面跟了 500 多字：

```
…的规定。之间或高层与其他建筑之间的防火间距，按本表规定增加3m；外墙为防火墙时，
其防火间距不限，但甲类厂房之间不应小于4m。两座丁、戊类生产厂房，当符合以下各项条件时…
```

这些字全部来自**表 4.2.10 的注**，而且分散在两页：

```
p12: 4.2.10 …不应小于表4.2.10 的规定。
p12: 表4.2.10 纺织工业工厂总平面布置的防火间距（m）
p13: 注：1 表中生产厂房、辅助生产建筑…均指单层或多层建筑。高层建筑
p13: 之间或高层与其他建筑之间的防火间距，按本表规定增加3m；   ← 第1条注的折行，无「注：」头
p13:    2 两座建筑物相邻较高一面的外墙为防火墙…
```

**根因**：p13 第 2 行是第 1 条注的折行，它既不带「注：」头、也不以数字开头，
所以没被任何规则识别，落到最后的"续行"分支 → 拼进了 `cur["body"]`。

**修法**：**表注区内的所有续行都进 `table_notes`，一律不进正文**。

```python
if in_table_zone:
    if cur["table_notes"]:
        cur["table_notes"][-1] += s     # 接到上一条注
    else:
        cur["table_notes"].append(s)
elif cur["kuan"]:
    cur["kuan"][-1]["text"] += s
else:
    cur["body"] = (cur["body"] + s).strip()
```

**怎么发现的**：交付后做独立复核，从 PDF 原文重新数条号 + 抽最长/最短条逐字对照。
自动校验（结构校验、缺陷扫描）100% 通过，但内容已经脏了。

> **教训：结构校验通过 ≠ 内容正确。**
> 必须有一步"拿原文反查"的独立复核——用**另一条代码路径**重算一遍，
> 而不是拿同一份解析结果反复自证。

## 表格 OCR 与合并单元格

表体是图片，用 RapidOCR 后按坐标还原：

```python
# 1. 按 y 中心聚类成行（容差 12px）
# 2. 行内按 x 排序成列
# 3. 罗马数字规范化（D04）：I → Ⅰ，II → Ⅱ（仅当后面跟 、，。时）
```

实测 23 张图里 **21 张是真表**，2 张是广告（宽 >1000px 要排除）。
识别出表4.1.7（20 行）、表4.2.9（11 行）、表4.2.10（30 行，含"续表"合并）。

**合并单元格的诚实处理**：跨行单元格被 OCR 切成两半（`生产厂房、辅助生产建筑（甲类` +
`仓库除外）、公用工程站`），单行看括号不配对。**不要去"修"数据**——如实记录
"OCR 按行聚类，未还原合并单元格"，比伪造一个整齐的表更有用。

## 顺序建议（省时间的顺序）

```
1. 体检（页数/字数/图片/水印）        ← 10 分钟，决定后面所有事
2. 定位结构边界（正文起点、附录、条文说明）
3. 抽取 + 清洗（水印/页码/空标记）
4. 解析（章/节/条/款）→ 每改一条规则就重跑，看条数/章数是否合理
5. 表格 OCR（只在确认表体是图片时做）
6. 生成 xlsx（8 页签）
7. 两步自动检查（结构校验 + 缺陷扫描）
8. 检索验收（命中@3 + 全款交付）
```

**第 4 步的判据**：章数应该等于公告/目录说的章数，条数应该连续无断号。
一旦数字不对，先别往下走——后面所有产出都是错的。
