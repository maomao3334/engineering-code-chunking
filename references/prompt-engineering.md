# 切分提示词工程 v0.1

> 用途：把 GB 55037-2022 这部规范已经人工核对过的切法，固化成一个**可复用的切分规则**。
> 目标：新规范丢进来，按同一套规则切，切完抽样 10 条复检，全对就入库。
> 状态：草稿，few-shot 直接用本库真实条文；第 2 步实测后升 v1.0。

---

## 一、任务定义

给你一份工程建设规范 PDF 的文本行（已 OCR，可能带行号、页眉页脚、错字），
把它切成三级结构，输出 JSON。**不解释、不总结、不改写原文**——只做分层和归位。

```
书 → 章（第N章）→ 节（N.M）→ 条（N.M.K）→ 款（1 2 3 / （1）（2））
```

---

## 二、切分规则清单

### R1 层级判定

| 形态 | 判定 |
|---|---|
| `3 建筑总平面布局` | 章 |
| `3.4 消防车道与消防车登高操作场地` | 节 |
| `3.4.5 消防车道应符合下列规定：` | 条（父块） |
| `1 ……；` `2 ……；` | 款（子块，父条号 = 上面那条） |
| `（1）……` | 二级款（父项号 = 上一层款号） |

**关键**：条号与它下面的款是**父子关系**，不是兄弟。`2.1.1` 和 `2.1.2` 是兄弟，`2.1.2` 下面的 `1 2 3 4` 是它的孩子（见 few-shot ①）。
**这是纯正则做不到的地方：正则看到数字就切，会把 1 2 3 4 切成和 2.1.2 平级。**

### R2 编号形态识别

- 只认**行首**编号，不认正文里的数字（"不小于 2 个"不是款号）
- 条号形态固定为 `数字.数字.数字`，如 `7.4.1`
- 款号是行首单个数字 + 空格，且**句末是 `；` 或 `。`**
- 括号款 `（1）` 只在明确从属某款时才算二级款，否则当正文

### R3 OCR 丢号的补法

原页有编号但 OCR 没识别出来时（本库共 19 处），按同一父条下的顺序补齐，
并在字段里标注 `条号来源 = OCR推断`，**不要静默补**。人工复核时优先看这些。

### R4 跨页合并

同一条被分页切断时合并成一条；页眉、页脚、页码、`— 15 —` 这类整行丢弃。

### R5 上下标与特殊符号

`m² m³ B₁ B₂ Ⅰ Ⅱ Ⅲ ℃` 按原书保留。OCR 常把它们识别成 `m2`、`B1`、`I II III`、`°C`，
必须还原成上标下标与罗马数字（本库修复了 62 条）。**同类规范对比时，`℃` 与 `°C` 视为等价。**

### R6 表格

表格**不并入条文正文**。条文里只保留"应符合表X的规定"，
表体单独结构化成：表号 / 表标题 / 所属条文 / 行列 / 单元格值。跨行合并单元格按语义展开，
原表里表示"不适用"的横线**不得写成 0**。

### R7 不给的东西不要造

PDF 里没有术语、条文说明、附录，就不要生成这些类型。字段如实写"无"。
不得臆造"0 节"，未设节的章统一写 `未设节`。

## 三、few-shot ①（父子关系，这是最容易被切错的地方）

**输入行：**
```
2.1.2 建筑防火应达到下列目标要求：
1 保障人身和财产安全及人身健康；
2 保障重要使用功能，保障生产、经营或重要设施运行的连续性；
3 保护公共利益；
4 保护环境、节约资源。
```

**正确输出：**
```json
{
  "条文号": "2.1.2",
  "章": "2 基本规定",
  "节": "2.1 目标与功能",
  "条文原文本体": "建筑防火应达到下列目标要求：\n1 保障人身和财产安全及人身健康；\n2 保障重要使用功能，保障生产、经营或重要设施运行的连续性；\n3 保护公共利益；\n4 保护环境、节约资源。",
  "款": [
    {"序": 1, "文": "保障人身和财产安全及人身健康；"},
    {"序": 2, "文": "保障重要使用功能，保障生产、经营或重要设施运行的连续性；"},
    {"序": 3, "文": "保护公共利益；"},
    {"序": 4, "文": "保护环境、节约资源。"}
  ],
  "列项数": 4
}
```

**错误的切法（务必避免）**：把 `1 2 3 4` 切成四条独立的条文，条号写成 `2.1.2-1`、`2.1.2-2`，
与 `2.1.2` 平级。这样切完，"建筑防火的目标是什么"这个问题只能捞到其中一款，答案必然漏。

## 四、few-shot ②（款里还带引用其他条，别把引用当切点）

**输入行：**
```
4.1.5 附设在建筑内的燃油或燃气锅炉房、柴油发电机房，除应符合本规范第4.1.4条的规定外，尚应符合下列规定：
1 常（负）压燃油或燃气锅炉房不应位于地下二层及以下……
```

**正确输出要点：** 全部归到 `4.1.5`，`第4.1.4条` 只是**正文里的交叉引用**，不是新条起点。
同时把引用关系记下来（`引用的条：4.1.4`），检索时可以顺手把 4.1.4 一并带上。

## 五、输出 schema

```json
{
  "规范全称": "",
  "规范编号": "",
  "条文号": "",
  "章": "",
  "节": "",
  "条文小标题": "",
  "条文原文本体": "",
  "款": [{"序": 1, "文": "", "二级款": [{"序": 1, "文": ""}]}],
  "列项数": 0,
  "关联表格": "",
  "引用的条": [],
  "是否强条": "",
  "PDF起页": 0,
  "PDF末页": 0,
  "条号来源": "原页编号 | OCR推断",
  "存疑": ["原文疑似缺字", "编号可能丢失"]
}
```

**`存疑` 字段很重要**：模型自己拿不准的地方必须报出来，不要硬编。人工复核只核「存疑」和抽样即可，
否则 200 部规范靠人逐条看是不可能的。

## 六、自检清单（让模型切完自己回头核一遍）

- [ ] 章号是否连续？有没有跳章？
- [ ] 每章的条号是否从 `x.0.1` 或 `x.1.1` 开始连续递增？有没有跳号、重号？
- [ ] 每个父条的 `列项数` 和 `款` 数组长度是否一致？
- [ ] 正文里出现的 `第X.X.X条` 是否都被记进了 `引用的条`，而没有被误切成新条？
- [ ] 有没有把表体混进正文？
- [ ] 有没有静默补编号？（必须标 `条号来源 = OCR推断`）
- [ ] 有没有臆造 PDF 里没有的内容（术语、附录、条文说明）？

## 七、已知失败模式（实测踩过的）

| 失败模式 | 后果 | 对策 |
|---|---|---|
| 看到数字就切 | 款被切成平级条文，父块丢失，答案漏款 | R1 + 自检第 3 项 |
| 把交叉引用当新条 | 条号错乱，检索串条 | R2 + few-shot ② |
| 表体并进正文 | 条文原文本体被污染，无法溯源 | R6 |
| 静默补编号 | 错也查不出来 | R3 + 标 `条号来源` |
| 臆造"未设节 = 0 节" | 章节结构与目次对不上 | R7 |

---

## 八、验收标准（第 2 步做完要满足）

1. 拿一部**新**规范（建议 20 条左右的小规范），跑一遍
2. 人工抽核 10 条：条号对、款数对、原文一字不差
3. 与 PDF 目次核：章数、节数、条号范围一致
4. 存疑项全部列出来，且抽核后确认 80% 以上是真存疑（不是模型偷懒）

全对之后，这份文档升 v1.0，作为 200 部规范入库的标准。
