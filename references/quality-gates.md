# 质检项与验收标准

> **一条命令跑完 A～C 与 E 关**：`python scripts/verify_delivery.py --corpus 语料库.xlsx --pdf 规范.pdf --allow <已知疑点>`
> 它只做编排与汇总，每关的检查逻辑仍在各自脚本里；`--json` 输出可接 CI。
> 另有 `python scripts/lint_schema.py <xlsx>` 先查字段契约（页签/必备列/表格来源标注/质检报告占位），
> 缺列直接失败——这类问题切片照样能过，但复审工作台会静默降级。

## A. 结构完整性（自动化，必过）

| 检查项 | 标准 | 不过怎么办 |
|---|---|---|
| 条文总数 | 与目次一致 | 回查 OCR 丢条 |
| 章/节数量 | 与目次一致 | 检查章标题识别 |
| 条文号连续性 | 各章从 `x.0.1` 或 `x.1.1` 起连续递增，无跳号无重号 | 检查 OCR 丢号 |
| 列项数一致性 | 父块的「列项数」= 子块数量 | 检查款解析 |
| 切片父子关系 | 每个子块的父条号都能在父块表里找到 | 检查父块是否漏切 |
| 切片 ID 唯一 | 全库无重复 | |
| 元数据头完整 | 每个切片全文第一行含 `｜` 分隔的完整头 | |

## B. 内容准确性（半自动 + 抽样）

| 检查项 | 标准 |
|---|---|
| OCR 置信度 | 记录每条最低置信度；< 0.90 的必须 600dpi 重识别 + 目视核对 |
| 上标下标 | 逐条对照原页；抽检 20 条 |
| 数字与单位 | 抽检全部含数字的条文 |
| 原文一字不差 | 随机抽 10 条逐字比对原页 |

## C. 与参考库比对（有则必做，性价比最高）

逐条比对条号 + 正文。差异分三类记录：

1. **可解释差异**（单位等价 `℃`/`°C`、对方把表格内联进正文、标点全半角）→ 不算错
2. **我们错** → 修
3. **对方错** → 记录，不改

实测：236/241 一致，5 条差异全部可解释。

> 汇报时这比"我们自己检查了一遍"有说服力得多。差异清单本身就是能力证明。

## D. 检索效果（**核心，别跳过**）

只看"切得整齐"没用。**必须用真实问题测**。

### 指标 1：命中@k
给一个真实业务问题，正确的那一条有没有进前 3 名。

### 指标 2：全款交付率
命中多款条文后，交给大模型的上下文里该条**全部款**是否都在。

### 参考值（GB 55037-2022，26 题）

| 配置 | 命中@1 | 命中@3 | 全款交付 |
|---|---|---|---|
| 平铺切片 | 17/26 | 22/26 | 62% |
| 父子块回溯 | 19/26 | 22/26 | **100%** |
| +表格独立成块 | 21/26 | 24/26 | 100% |
| +查询改写 +引用闭合 | **23/26** | **26/26** | 100% |

**全款交付 62% → 100% 是父子块结构最硬的证据。** 汇报时就讲这个数字。

### 问题集怎么出

至少 7 类，每类 2~4 题：

1. **直接术语**——"甲类厂房的防火间距是多少"
2. **数字与单位**——"消防电梯前室使用面积最小多少"
3. **多款完整性**——"哪些工业建筑耐火等级不应低于二级"（考漏款）
4. **表格依赖**——"四级耐火等级只设一个安全出口最多几层"（考表格）
5. **情境化**——"三层小商场每层200平，第二三层共50人，能不能只做一个出口"
6. **口语化**——"楼里着火了人跑不出来，规范对逃生有什么要求"（考语义鸿沟）
7. **低价值条款**——"违反规范怎么处罚"（考废话过滤）
8. **规范未规定**——"电动车能不能进电梯"（考拒答能力）

> 第 8 类必须有。规范类问答最容易出的错不是"检索不到"，是"编得像"。

### 别犯的错

**不要用同一批题既调参又报指标。** 同义词表/阈值如果是对着这 20 题写出来的，那 20/20 是自证。
调参用 70%，留 30% 做留出集，或者事后扩到 50+ 题再验一遍。

## E. 人工复审（第四关，不能省）

### 为什么必须有这一关

A/B/C/D 全部是**自动化或抽样**检查，它们证明的是"结构没漏、字没串行、切片对得上、检索能命中"，
**证明不了"这一条与原件逐字一致"**。实测反例：某条正文后面被塞进 500 字表注，
A（结构）与缺陷扫描 100% 通过——自动化看不见"内容对不对"，只看得见"形状对不对"。

### 怎么组织：按不确定度降序，不按条号

`python scripts/build_review_workbench.py 语料库.xlsx`

输出 `人工复审工作台.xlsx`：`01-复审队列` 把全部待判对象按**不确定度（0-100）从高到低**排，
每行带「为什么排这里」的打分依据（如"表体为图片·视觉转录 +35；原表内部不自洽 +25"）与 P0-P3 优先级。

排序依据（全部从工作簿元数据算出，不需要人工打分）：

| 维度 | 典型加分 |
|---|---|
| 来源可靠性 | 图片表格视觉转录 +35；公式渲染图还原 +20~35；几何识别下划线 +25；扫描污损 +10~20；文字层 0 |
| 内部矛盾 | 原表自相矛盾 +25；格式不统一 +10 |
| 已登记存疑 | 高 +45 / 中 +30 / 低 +15 |
| 结构性脆弱点 | A/B 后缀 +8；跨页 +6；结尾非句读 +10；已删除条 +12；公式占位 +10；页级元素 +5；附录整册 +8 |
| 复核覆盖缺口 | 无独立交叉校验 +15（有则 -5） |

### 四条纪律

1. **不按条号顺序发清单**。90% 条文是低风险项，按条号翻会把注意力平摊，真正会错的地方被稀释。
2. **不写"预计工时"**。不同规范条数差 10 倍、图片表格占比差 10 倍，工时估算一律是拍脑袋；
   给对象数与优先级分布（P0 5／P1 23／P2 53／P3 110），让团队自己排人。
3. **原件排印错误默认不改字**。改了会让用户搜原词搜不到，也没法与纸质版对照。
   正确处理：加括注 / 检索侧同义词 / 登记「存疑保留」。
4. **修正回灌脚本，不手改 xlsx**。xlsx 是脚本产物，手改会被下次重跑覆盖。

### 验收线

- `02-汇总` 里「待核」归零；
- 每条「需修改」都写明**改成什么 + 依据哪一处**；
- 回灌后重跑 A/B/C 三项，四项指标（漏条 0 / 编造 0 / 保真 100% / 切片对账一致）不退化。

## F. 汇报用的三个数字

如果只能讲三个数，讲这三个：

1. **切分正确性**：241 条 / 与参考库 236 条一致，5 条差异可解释
2. **检索有效性**：命中@3 26/26
3. **父子块的必要性**：全款交付 62% → 100%

第 3 个是关键。它证明"我们这么切"不是审美选择，是有量化收益的工程决策。
